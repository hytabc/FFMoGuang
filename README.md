# 魔光键影助手（FFMoGuang）

国服 Dalamud API 15 / .NET 10 插件。用户开启后，连续读取已绑定的游戏目标词条，写入游戏输入栏，再调用该输入控件自身注册的 Enter 回调。通过 `SetText` 写入，不使用 Ctrl+C/V、剪贴板或系统模拟按键。

当前版本 **0.1.1.0** 已根据用户在实际对局中导出的两份 UI 数据，加入区域 **1359** 的自动节点绑定。已确认输入框和目标词条的真实节点；完整的填写、提交和命中效果仍待实机验收。

## 加载和首次使用

1. 构建产物为 `artifacts/FFMoGuang-0.1.1.0.zip`。升级时先卸载旧插件，替换同目录中的文件，再重新加载。解压后保留 `FFMoGuang.dll`、`FFMoGuang.Core.dll`、`FFMoGuang.deps.json` 和 `FFMoGuang.json` 在同一目录。
2. 打开 Dalamud 设置的「开发插件 / Dev Plugins」，将解压后的 `FFMoGuang.dll` 完整路径添加为开发插件位置，随后在开发插件列表中加载。也可直接使用本项目 `FFMoGuang/bin/Release/FFMoGuang.dll`。不要只复制主 DLL 而遗漏 Core DLL。
3. 进入魔光键影的**实际对局**（区域 1359），等待敌人词条出现，输入 `/mg` 打开面板。
4. 点击「自动绑定魔光键影」（也可用 `/mg bind`）。插件会检查当前游戏版本、输入回调和全部词条槽位，成功后保存绑定。没有配置的情况下，首次点击「开始」也会自动识别。
5. 确认面板显示「当前区域：1359」「绑定区域：1359」，输入框为 `KTGInput[1]/7`，已绑定词条数为 20；所有槽位均绑定，包括当前隐藏、后续波次使用的槽位。
6. 核对面板中的「可见目标」与当前屏幕一致，清空游戏输入栏，设置主面板中的「操作延迟（ms，填入 → 提交）」和「答题间隔（ms）」，点击「开始」。游戏窗口须保持前台。
7. 按 **F8**、点击「停止」或使用 `/mg stop` 可停止。插件不会自动排队、重新入场、领取奖励或在重新加载后自动开启。

若检查器找不到目标词条，使用 `/mg dump`，导出位置会显示在面板和聊天日志中。导出仅写入本机插件配置目录，可能包含当时可见的聊天等 UI 文本，分享前可删去无关条目。可根据实际节点数据继续增加适配，无须猜测内存偏移。

### 内置适配与手动绑定

内置适配对应导出中的游戏版本 `2026.10.06.0000.0000`、区域 `1359`：输入框 `KTGInput[1]/7`；目标词条 `KTGEWord[1]/2/20` 和 `KTGEWord[1]/20001/20` 至 `KTGEWord[1]/20019/20`。自动绑定要求所有 20 个槽位结构匹配，且至少有一个实际可见词条；不猜测其他文本节点的用途。已有完整的手动配置不会在点击开始时被自动覆盖，自动绑定失败也不会覆盖现有配置。

其他版本可展开「节点检查与绑定」，勾选「仅输入框」选择游戏输入栏，再取消勾选、按屏幕词条搜索并逐个绑定目标槽位。检查器每 750ms 刷新；所有原生节点读取和调用均在 Framework 线程执行。不要选择聊天输入框、计分、玩家名或操作提示。

旧版遇到空配置（`Territory=0`、`Input=null`、`Words=[]`）时误报「当前区域与绑定区域不一致」。0.1.1 已修复：空配置显示尚未绑定并可自动识别；真正的区域不一致会同时显示当前区域和绑定区域。无需手动编辑配置文件中的区域数字。

## 自动答题行为

- 只读取明确绑定的节点，沿组件路径逐级查找节点 ID；歧义 ID 不会用于输入。控件或其父节点隐藏、透明或禁用时不会输入。
- 面板同时显示「开始」和「停止」按钮，运行中「开始」禁用，「停止」保持可点击，F8 和 `/mg stop` 同样可用。
- 主面板支持两个整数毫秒参数：「操作延迟」为填入到提交的等待，默认 100ms；「答题间隔」为输入清空到下一次选词的等待，默认 650ms。两者范围均为 0–60000ms，0 表示不额外等待；控制器每 50ms 轮询，实际等待会向后取到下次轮询，并非精确计时承诺。词条稳定时间另默认为 150ms。
- 点击「开始」会应用并保存当前延迟；也可单独点击「保存延迟」。运行中保存会停止答题，需重新开始。参数持久化至 Dalamud 插件配置，重新加载保留；界面显示已保存数值。
- 填入后于提交前重新校验目标、输入内容、区域和界面实例。保留中文、Unicode、空格和标点；去除 SeString 的颜色等显示载荷，不对词条做裁剪或替换。空词、控制字符和超过 512 个 UTF-8 字节的文本不参与答题。
- 使用输入控件的 `SetText`，要求原始文本和求值文本都与目标完全相同；截断、字符过滤等情况立即停止，不发送错误内容。
- 调用 `AtkComponentInputBase.Callback`，传入 `InputCallbackType.Enter`、真实 `CallbackEventKind` 和独立 UTF-8 缓冲区。若返回 `ClearText`，重新解析节点后清除仍属于本次填写的内容；不支持的回调结果会停止。
- 提交后等待输入清空，默认间隔 650ms。输入清空只表示回调已消费输入，**不等于服务器确认攻击成功**；面板计数为「提交调用」，不声称击杀数。
- 多个目标轮流处理，同等提交次数时优先较短词条。同一仍可见词条允许重复攻击，默认最多 5 次；目标消失或换词后重置次数。可在面板调整上限至 1–100，防止无反馈时持续刷同一词条。
- 手动改字、输入两秒未清空、切区、登出、界面重建或关闭、游戏 UI 隐藏、窗口失焦时停止。停止不清除遗留文本，重新启动前需自行检查并清空输入栏。
- 绑定记录区域和游戏版本。客户端更新后必须重新绑定；更新后的 Dalamud/FFXIVClientStructs 仍需重新编译和实机核验。没有持久化的自动启动开关。

## 构建与验证

安装 .NET SDK 10，以及国服 Dalamud 的开发程序集。项目使用 `Dalamud.CN.NET.Sdk/15.0.0`，默认查找 `%APPDATA%/XIVLauncherCN/addon/Hooks/dev/`；使用其他位置时先设置 `DALAMUD_HOME` 指向对应程序集目录。

```powershell
./build.ps1
```

脚本构建整个解决方案、运行控制器测试，并核对 ZIP 包含主 DLL、Core DLL 和清单且不包含 Dalamud 运行库，然后复制发布包到 `artifacts/`。

也可以分别执行：

```powershell
dotnet build FFMoGuang.slnx --configuration Release
dotnet run --project tests/FFMoGuang.Tests --configuration Release
```

测试工程是无外部测试包依赖的控制台验证程序，失败返回非零退出码，需使用 `dotnet run`，不要以 `dotnet test` 的空结果代替验证。当前 33 项验证覆盖中文和标点保真、目标变化与消失、重复词条和多目标、等待新波次、手动干预、界面重建、停止取消、提交失败、超时与限流，以及自定义毫秒操作延迟、答题间隔、零延迟与上下界。

`tests/FFMoGuang.Tests/fixtures/` 中的两份样例提取自用户 2026-10-28 17:28 的真实对局导出，只保留输入框和目标词条，排除聊天、玩家名等无关数据。回归验证包含空配置提示、两种波次均绑定全部 20 槽位、错误区域/版本、缺失或重复节点、输入框隐藏或无回调、无可见敌人等情况。

## 实机验收清单

1. 输入栏和各目标词条能在检查器内找到，绑定后预览随屏幕更新，已消失或隐藏的词条不再参与答题。
2. 首次开启时观察一次填写与提交：游戏确认命中，输入栏恢复空白；中文、标点及长词条均正确。
3. 多目标、新波次及需要多次攻击的敌人能持续处理，提交次数有节流。
4. 目标在填入后被队友击倒时，不提交旧目标；手动修改输入后停止且保留人工文本。
5. F8、切窗口、退出对局和切区域均停止；再次加载插件不会自动开始。

以上实机项目未执行前，应将该版本视为待联调，不能把编译和控制器测试通过当成游戏内可用证明。
