# 魔光键影助手（FFMoGuang）

国服 Dalamud API 15 / .NET 10 插件。用户开启后，连续读取已绑定的游戏目标词条，选择直接填词或实验性键盘逐字输入，并选择自动或手动 Enter 提交。不使用 Ctrl+C/V 或剪贴板。

当前版本 **0.3.3.0**，区域 **1359**，新增自动提交的随机操作延迟区间，保留 **F9 开始 / F8 停止**。用户已验证此前直接填词的自动答题可用，但仍反馈无操作强制退出；Unicode 与 Shift 方案不能据此视为有效。已加入搜狗全拼字母输入、可调随机节奏，并修正采样被重复刷新挤满的问题。输入法兼容性和 AFK 计时重置效果尚未实机确认。队友及完全手打发送的数据源尚未接入，不会把缺失数据显示为零。

## 加载和首次使用

1. 构建产物为 `artifacts/FFMoGuang-0.3.3.0.zip`。升级时先卸载旧插件，替换同目录中的文件，再重新加载。解压后保留 `FFMoGuang.dll`、`FFMoGuang.Core.dll`、`FFMoGuang.deps.json` 和 `FFMoGuang.json` 在同一目录。旧绑定和延迟配置可继续使用，搜狗全拼及随机提交默认关闭；未配置提交模式时默认为自动提交。
2. 打开 Dalamud 设置的「开发插件 / Dev Plugins」，将解压后的 `FFMoGuang.dll` 完整路径添加为开发插件位置，随后在开发插件列表中加载。也可直接使用本项目 `FFMoGuang/bin/Release/FFMoGuang.dll`。不要只复制主 DLL 而遗漏 Core DLL。
3. 进入魔光键影的**实际对局**（区域 1359），等待敌人词条出现，输入 `/mg` 打开面板。
4. 点击「自动绑定魔光键影」（也可用 `/mg bind`）。插件会检查当前游戏版本、输入回调和全部词条槽位，成功后保存绑定。没有配置的情况下，首次点击「开始」也会自动识别。
5. 确认面板显示「当前区域：1359」「绑定区域：1359」，输入框为 `KTGInput[1]/7`，已绑定词条数为 20；所有槽位均绑定，包括当前隐藏、后续波次使用的槽位。
6. 核对面板中的「可见目标」与当前屏幕一致，选择输入方式及「自动提交」或「手动 Enter 提交」，清空游戏输入栏，设置延迟并点击「开始」。游戏窗口须保持前台；逐字输入或手动提交时请将焦点放回游戏输入框。
7. 游戏前台按 **F9** 可按已保存的模式和延迟开始，面板关闭时也有效；新编辑的延迟请先保存。按住不会重复启动；启动失败后须松开再按，同时按 F8 时停止优先。按 **F8**、点击「停止」或使用 `/mg stop` 可停止。插件不会自动排队、重新入场、领取奖励或在重新加载后自动开启。

若检查器找不到目标词条，使用 `/mg dump`，导出位置会显示在面板和聊天日志中。导出仅写入本机插件配置目录，可能包含当时可见的聊天等 UI 文本，分享前可删去无关条目。可根据实际节点数据继续增加适配，无须猜测内存偏移。

### 内置适配与手动绑定

内置适配对应导出中的游戏版本 `2026.10.06.0000.0000`、区域 `1359`：输入框 `KTGInput[1]/7`；目标词条 `KTGEWord[1]/2/20` 和 `KTGEWord[1]/20001/20` 至 `KTGEWord[1]/20019/20`。自动绑定要求所有 20 个槽位结构匹配，且至少有一个实际可见词条；不猜测其他文本节点的用途。已有完整的手动配置不会在点击开始时被自动覆盖，自动绑定失败也不会覆盖现有配置。

其他版本可展开「节点检查与绑定」，勾选「仅输入框」选择游戏输入栏，再取消勾选、按屏幕词条搜索并逐个绑定目标槽位。检查器每 750ms 刷新；所有原生节点读取和调用均在 Framework 线程执行。不要选择聊天输入框、计分、玩家名或操作提示。

旧版遇到空配置（`Territory=0`、`Input=null`、`Words=[]`）时误报「当前区域与绑定区域不一致」。0.1.1 已修复：空配置显示尚未绑定并可自动识别；真正的区域不一致会同时显示当前区域和绑定区域。无需手动编辑配置文件中的区域数字。

## 直接填词与自动提交行为

- 只读取明确绑定的节点，沿组件路径逐级查找节点 ID；歧义 ID 不会用于输入。控件或其父节点隐藏、透明或禁用时不会输入。
- 面板同时显示「开始（F9）」和「停止（F8）」按钮，运行中「开始」禁用，「停止」保持可点击。F9 与 `/mg start` 使用已保存参数；运行中再按 F9 不重启。
- 主面板支持两个整数毫秒参数：「操作延迟」为填入到提交的等待，默认 100ms；「答题间隔」为输入清空到下一次选词的等待，默认 650ms。两者范围均为 0–60000ms，0 表示不额外等待；控制器每 50ms 轮询，实际等待会向后取到下次轮询，并非精确计时承诺。词条稳定时间另默认为 150ms。
- 勾选「自动提交使用随机操作延迟」后，设置下限、上限（默认 100–300ms，允许 0–60000ms），每次完整填词或逐字输入确认完成后，在包含两端的整数区间内均匀取值一次，再等待提交；轮询不会重复抽取，面板显示本次等待值。上限小于下限时保存为与下限相等，两个值相等即固定等待。关闭勾选恢复原固定延迟。
- 此随机操作延迟适用于直接填词、Unicode 及搜狗全拼的自动提交；手动 Enter 模式忽略该设置。它独立于逐字输入的随机节奏，不会改变答题间隔，也不会额外加入区间外的随机停顿。等待中仍检查目标、输入文本与游戏状态。
- 点击「开始」会应用并保存当前延迟；也可单独点击「保存延迟」。运行中保存会停止答题，需重新开始。参数持久化至 Dalamud 插件配置，重新加载保留；界面显示已保存数值。
- 填入后于提交前重新校验目标、输入内容、区域和界面实例。保留中文、Unicode、空格和标点；去除 SeString 的颜色等显示载荷，不对词条做裁剪或替换。空词、控制字符和超过 512 个 UTF-8 字节的文本不参与答题。
- 使用输入控件的 `SetText`，要求原始文本和求值文本都与目标完全相同；截断、字符过滤等情况立即停止，不发送错误内容。
- 调用 `AtkComponentInputBase.Callback`，传入 `InputCallbackType.Enter`、真实 `CallbackEventKind` 和独立 UTF-8 缓冲区。若返回 `ClearText`，重新解析节点后清除仍属于本次填写的内容；不支持的回调结果会停止。
- 提交后等待输入清空，默认间隔 650ms。输入清空只表示回调已消费输入，**不等于服务器确认攻击成功**；面板计数为「自动提交请求」，不声称击杀数。直接填词时计数对应回调调用，逐字模式对应系统接受的 Enter 按下请求。
- 多个目标轮流处理，同等提交次数时优先较短词条。同一仍可见词条允许重复攻击，默认最多 5 次；目标消失或换词后重置次数。可在面板调整上限至 1–100，防止无反馈时持续刷同一词条。
- 手动改字、输入两秒未清空、切区、登出、界面重建或关闭、游戏 UI 隐藏、窗口失焦时停止。停止不清除遗留文本，重新启动前需自行检查并清空输入栏。
- 绑定记录区域和游戏版本。客户端更新后必须重新绑定；更新后的 Dalamud/FFXIVClientStructs 仍需重新编译和实机核验。没有持久化的自动启动开关。

## 模拟键盘逐字输入（实验）

普通按键或 `SetText` 加 Enter 可能没有触发游戏所需的文本输入事件。为测试这一假设，本版增加独立的输入路径，默认仍为此前已可用的「直接填词」。两项选择可以组合：

| 输入方式 | 自动提交 | 手动 Enter 提交 |
| --- | --- | --- |
| 直接填词 | `SetText` + 输入控件回调 | `SetText` + 玩家 Enter |
| 模拟键盘逐字输入 | Windows Unicode 逐字输入 + 扫描码 Enter | Windows Unicode 逐字输入 + 玩家 Enter |

使用步骤：

1. 选择「Unicode 逐字输入（实验）」，选择自动或手动提交，设置「逐字间隔」。默认 40ms，范围 0–1000ms；答题每 50ms 轮询，实际每个轮询最多发送一个 Unicode 码点，不承诺精确毫秒间隔。开启随机节奏后，使用下文的随机间隔。
2. 清空游戏输入栏、结束输入法组合状态，点击「开始」，再点击小游戏输入栏。光标须在末尾，且没有文字选区。未开始打字时插件会等待输入焦点，不会自动抢焦点。
3. 观察一个完整词条逐字出现。插件读取到每个字符的预期结果后才继续，不会在字符丢失后反复重发或回退为 `SetText`。
4. 自动模式核对完整文本与求值文本后，模拟按下主键盘 Enter 约 120ms，再释放；手动模式请等面板显示输入完成后亲自按 Enter。

逐字发送使用 `SendInput` 的 Unicode 按下/抬起事件，非 BMP 字符按完整 UTF-16 代理对发送；模拟 Enter 使用扫描码 `0x1C`。不调用 `SetText`、提交回调或剪贴板来完成该路径的输入与提交。它仍是软件注入，**不等同于实体键盘、拼音输入法或硬件 Raw Input**，游戏是否接收中文、是否将其计为活动均未知。

只有游戏前台、区域和版本正确、小游戏绑定输入框为当前活动文本输入目标、光标在末尾且没有选区、Dalamud 界面没有捕获键盘时才输入。发送字符和 Enter 前另检查 Ctrl、Shift、Alt、Windows 键和 Enter 均已松开。开始打字后失焦、人工修改、切区、目标消失或单字默认 2 秒未读到预期文字均停止并保留残留文本。F8、停止、失焦和卸载会释放插件持有的按键，运行中释放失败会重试。重新开始前请手动清空残留。

逐字模式暂停左 Shift 心跳，避免两种输入同时发生。验证时先观察文字接收与命中，再分别观察 60 秒及 15 分钟退出情况；本地测试没有向游戏实际发送模拟按键，不能据此断言退出问题已解决。

## 搜狗全拼字母输入与随机节奏（实验）

用户当前使用搜狗全拼。本版单独增加经输入法转换的路径：**汉字 → 全拼字母扫描码 → 搜狗候选页 → 完全相同的候选字 → 核对整条词语 → Enter**。它按字组词，不直接用 Unicode 写入汉字；标点及其他非汉字仍使用 Unicode 输入。

1. 切换到搜狗**全拼中文状态**，关闭 Caps Lock。取消未结束的输入法组合并清空游戏输入栏。
2. 面板选择「搜狗全拼字母输入（实验）」及自动或手动 Enter 提交。选择该模式时会默认启用「随机输入节奏」。
3. 点击开始，再点击小游戏输入栏。面板显示当前汉字、拼音字母进度和候选翻页数。
4. 插件逐个按下并抬起字母，读取当前候选页；只选择与目标汉字完全相同的候选。首候选用空格，后续候选用数字，找不到时最多 PageDown 十次；页不再变化则停止。
5. 每个字必须已结束输入法组合、读到正确文字且相关按键已释放，才处理下一字。整个词条与游戏求值文本均一致后，才模拟 Enter 或等待玩家 Enter。

随机设置为每次动作间隔 **60–160ms**（默认），界面可调整上下限至 20–1000ms；每次另有约 **12%** 概率增加 **180–420ms** 停顿。全拼字母和候选键按住 **35–80ms**；关闭随机后按住 50ms、使用普通逐字间隔。候选翻页另等 200ms，字符确认及游戏帧率也会增加实际等待。随机间隔每次只采样一次，不会因反复轮询而改变同一次等待；不会自动制造错误或发送错误词条。

读音采用内置字典的首读音，`ü` 按搜狗全拼习惯转换为 `v`；不使用上下文多音字判断。未知字、无法读取中文状态、无法读取候选页、候选不匹配或输入内容被修改都会停止，不猜选，不回退到直接填字。每字输入最多 30 秒；候选选中后默认 2 秒仍未得到目标字就停止。重启前请手动取消残留组合并清空文本。

本版通过 Windows IMM 接口读取输入法状态与候选。搜狗版本、TSF/IMM 兼容情况和游戏焦点处理可能使候选不可读；这种情况下本版本仍不能自动完成输入，面板会显示停止原因，不能将本地测试当作实机兼容证明。搜狗全拼时暂停 Shift 心跳，因为单独 Shift 可能切换中英文。字母输入与随机节奏也不保证重置游戏的无操作计时。

拼音数据来自 [pinyin-data 0.15.0](https://github.com/mozillazg/pinyin-data)，MIT 许可证。原始字典和许可证位于 `FFMoGuang.Core/Resources/`，均嵌入 Core DLL。

## 手动 Enter 提交

在主面板选择「手动 Enter 提交」，然后点击「开始」。插件选词并填入后显示「请在游戏输入框按 Enter 提交」，等待玩家亲自按键，不会调用提交回调。请确保焦点在游戏的输入框。

- 等待玩家按 Enter 不设答题超时；「操作延迟」在此模式下禁用。「答题间隔」仍决定提交清空后多久开始选择下一条。
- 每帧观察 Enter 按键边沿，不吞掉按键。观察到 Enter 后输入框清空，才继续下一条；按键后默认 2 秒仍未清空则停止，不会补发。
- 按住 Enter 时暂停填入下一条，松开后再选词，防止长按连发。直接填词时目标在提交前消失会清除仍属于插件的文本并重新选词；逐字模式则停止并保留残留文本。
- 手动改字、未观察到 Enter 就清空文本、失焦、界面重建或 F8 等情况仍会停止。停止保留遗留文本，重新开始前请检查并清空。
- 切换模式会保存设置并停止当前运行，不会自动恢复；重新加载保留模式选择。手动模式暂停键盘心跳。
- 顶部区分「自动提交请求」和「手动 Enter 清空」。后者只是插件填词后按键与输入清空的组合观察，不保证服务器命中，也不能排除按键后人工删除等情况。完全手打的词条不统计。

手动 Enter 提交是否能避免 60 秒或 15 分钟退出，仍需实机验证。

## 四人发送排行榜

面板默认展开「四人发送排行榜」，从已确认的 `KTGPlayerName` 节点读取四人姓名，并与本机角色名匹配，标记自己。名单每 250ms 更新，统计约每 50ms 刷新；未读取到的姓名显示占位文字。

- 当前统计**自己的直接提交回调调用，以及本插件填词后模拟或手动 Enter 加输入清空的观察**，显示合计次数、累计字数和速度。逐字模式仅向系统发出 Enter 但输入尚未清空时，不增加排行榜数据。它不代表服务器确认的有效攻击，也不包含完全手打发送。
- 队友显示「暂无发送数据」，暂不参与有效排名。取得能关联队员与发送内容的实机采样后，才能接入队友统计。
- 速度为最近 10 秒发送字数乘以 6，单位为字/分钟；启动初期也使用固定 10 秒窗口。字数按 Unicode 码点计算，包含空格和标点。
- 可按速度或累计字数排序，进度条以当前第一名的对应数值为满格；自己用蓝色，未知数据用灰色。
- 「清空统计」立即清零已记录数据。输入界面实例改变时重置；临时隐藏或离开界面时保留统计并冻结速度，恢复同一实例后继续统计。游戏若复用同一实例，不保证按每场比赛自动清零，可手动清空。统计不保存到磁盘。

## 键盘心跳与退出问题

用户反馈：约 60 秒没有真实键盘输入会 AFK 退出，另有约 15 分钟无操作退出。判定可能涉及一次完整的文本输入及发送，当前没有足够证据确定机制。原有左 Shift 心跳保留供对照，**默认关闭，尚未确认能重置上述任一种计时**；完整逐字输入的实验方式见上文。

在面板展开「键盘心跳（防无输入超时，待实机验证）」，勾选「启用前台键盘心跳（左 Shift）」。默认每 30000ms 短按左 Shift，间隔可设为 10000–45000ms，按住约 120ms 后释放；实际释放时间受游戏帧率影响。

心跳仅随「直接填词」加「自动提交」运行，手动 Enter 或逐字输入时暂停心跳；要求游戏前台、区域及版本匹配、绑定输入框可见且可用；按住 Ctrl、Shift、Alt 或 Windows 键时等待。停止、失焦、关闭心跳或卸载时会释放插件按下的键，运行期间释放失败会重试。心跳设置会保存，插件重新加载仍需手动开始答题。

面板的心跳次数只表示 Windows 接受了模拟按键，不能证明游戏把它当作真实输入。应分别观察超过 60 秒和超过 15 分钟的表现；若 15 分钟属于副本固定时限，键盘心跳不能延长时限。开发验证未向实际游戏发送模拟按键。

## 队友发送数据采样

当前已确认的 UI 导出包含玩家姓名和目标词条，但不足以确认每个队友的发送次数、字数。后续方便实机测试时，可按以下步骤收集数据：

用户提供的 2026-10-28 三份采样已分析：每份 2048 条，但只保留约 **1.312 秒**；分别溢出 4224、38087、38087 条，后两份为同一次采样的重复导出。留存内容没有可靠的“队员 + 发送词条”对应，不能把姓名旁的整数或计分刷新当作发送次数。分析报告见 `artifacts/capture-analysis-20261028.md`，原文件未修改。

0.3.1 过滤已确认的布局刷新，按命令和玩家槽位去重，只对 `KTGHudScore` 命令 1 的高频数值变化做 100ms 限频；其他事件和每次提交观察不做该限频。导出增加原始事件、重复、布局、计分限频及溢出的计数，字符串同时保留显示文本与原始 SeString 字节。这样避免早期的关键事件被每帧重复刷新挤掉；仍不能保证游戏必定通过这些界面公开队友发送明细。

新增的 `typing-capture-20261028-195327.json` 已分析：263 条事件覆盖约 29.891 秒，溢出为零；包含本人自动提交 15 次、33 字，以及 27 条目标相关刷新。后者只有命令与 UInt 标识，尚无可靠的发送者对应关系，不能用来计算队友字数或速度。分析报告见 `artifacts/capture-analysis-20261028-195327.md`。0.3.3 进一步将去重限定为姓名命令 0、输入提示命令 6、计分命令 1；目标及其他未知事件即使参数相同也保留，避免丢失可能的独立操作。

1. 进入对局，展开「发送数据采样（接入队友统计）」，点击「开始采样 30 秒」。
2. 让自己和队友分别发送几次词条，最好错开时间，便于关联；自己的直接提交调用及模拟或手动 Enter 后清空的时间会记录为参照，文件用不同事件名区分。
3. 点击「停止并导出采样」。30 秒后自动停止采集，但仍需点击导出保存。
4. 文件位于 `%APPDATA%\XIVLauncherCN\pluginConfigs\FFMoGuang\typing-capture-yyyyMMdd-HHmmss.json`，面板及聊天日志会显示完整路径。

采样仅记录列出的小游戏界面（`KTGInput`、`KTGPlayerName`、`KTGEWord`、`KTGHudLog`、`KTGHudScore`、`KTGResult` 及开始/过关/失败提示）的刷新、建立和销毁事件，以及插件直接提交内容和辅助填词后的模拟或手动 Enter 清空观察，不记录普通聊天。最多保留 2048 条事件，每条最多复制 64 个刷新参数，字符串最多 512 字节；超限丢弃数量随文件导出。文件仅写入本机，分享前可检查其中的玩家名与文本。

## 构建与验证

安装 .NET SDK 10，以及国服 Dalamud 的开发程序集。项目使用 `Dalamud.CN.NET.Sdk/15.0.0`，默认查找 `%APPDATA%/XIVLauncherCN/addon/Hooks/dev/`；使用其他位置时先设置 `DALAMUD_HOME` 指向对应程序集目录。

```powershell
./build.ps1
```

脚本构建整个解决方案、运行回归测试，并核对 ZIP 包含主 DLL、Core DLL 和清单且不包含 Dalamud 运行库，然后复制发布包到 `artifacts/`。

也可以分别执行：

```powershell
dotnet build FFMoGuang.slnx --configuration Release
dotnet run --project tests/FFMoGuang.Tests --configuration Release
```

测试工程是无外部测试包依赖的控制台验证程序，失败返回非零退出码，需使用 `dotnet run`，不要以 `dotnet test` 的空结果代替验证。当前 103 项验证覆盖中文和标点保真、目标变化与消失、重复词条和多目标、等待新波次、手动干预、界面重建、停止取消、提交失败、超时与限流，以及自定义毫秒操作延迟、答题间隔、零延迟与上下界。也覆盖四人排序、未知数据、Unicode 字数、滚动速度、界面恢复与重置，以及心跳间隔、前台限制、修饰键等待、停止释放、失败重试和 Win64 输入结构布局。手动模式有 12 项验证，覆盖长时间等待不自动提交、Enter 与清空组合计数、答题间隔、长按与启动前按住 Enter、无清空超时、改字或无按键清空停止、目标消失、停止取消、提交上限及旧配置兼容。

逐字模式新增 16 项验证，覆盖等待焦点、Unicode 代理对、逐字确认与间隔、手动 Enter 配合、焦点丢失与人工改字、目标消失保留文本、按键失败与提交清空、旧配置默认方式、部分注入失败后的释放重试、扫描码 Enter 持有和停止释放。键盘测试均使用模拟接口，不执行系统按键；游戏原生焦点字段及 Unicode 接收行为仍需实机验证。

0.3.1 新增 19 项验证，覆盖真实字典、字母扫描码、精确候选、翻页、转换未完成时禁止提交、输入法状态与超时、失焦释放、随机范围与设置兼容、原生候选偏移边界，以及基于脱敏实机结构回放 30 秒刷新、队员去重、重复提交保留、计分限频和溢出计数。这些验证不连接搜狗输入法，不验证 AFK 判定。

## 实机验收清单

用户已确认此前自动答题可用，以下用于升级回归及新增功能验收：

1. 输入栏和各目标词条能在检查器内找到，绑定后预览随屏幕更新，已消失或隐藏的词条不再参与答题。
2. 首次开启时观察一次填写与提交：游戏确认命中，输入栏恢复空白；中文、标点及长词条均正确。
3. 多目标、新波次及需要多次攻击的敌人能持续处理，提交次数有节流。
4. 目标在填入后被队友击倒时，不提交旧目标；手动修改输入后停止且保留人工文本。
5. F8、切窗口、退出对局和切区域均停止；再次加载插件不会自动开始。
6. 四人姓名和自己的标记正确；每次直接提交回调、辅助填词后的模拟或手动 Enter 清空仅增加一次统计，完全手打不计入，队友仍显示暂无数据。停止答题 10 秒后自己的速度降为零。
7. 开启心跳后，在前台持续答题，分别观察超过 60 秒及 15 分钟是否仍被退出；记录退出提示，区分无操作判定与固定时限。F8、停止、失焦后不继续发起按键。
8. 手动开启 30 秒采样后能够导出 JSON，包含自己提交及小游戏刷新事件。此项通过仍不代表已经识别了队友发送数据。
9. 手动模式填词后保持等待，只有亲自按 Enter 才提交；提交清空后按设定间隔填下一条。按住 Enter 时不填下一条；切换模式保存并停止，重新加载模式保留。分别测试主键盘 Enter 和小键盘 Enter。
10. 逐字模式开始后等待输入框焦点；点击输入栏后中文、标点及非 BMP 字符逐字出现，自动模拟 Enter 或等待玩家 Enter。中途转到聊天、操作其他 Dalamud 输入框、切窗口或按 F8 后不继续发送。分别观察 60 秒与 15 分钟退出情况，记录退出提示及最后一次完整输入时间。
11. 搜狗全拼模式确认字母实际进入输入法、候选能读取并精确选择；多音字、生僻字和中断时会停止而不提交错误文字。确认按键时长和间隔变化；分别观察无操作退出是否还发生。
12. 新采样覆盖整个采集过程，重复与布局计数递增，溢出为零或显著减少；检查能否找到队友发送变化，尚未确认前排行榜仍显示暂无数据。
13. 勾选随机操作延迟，设置如 200–800ms，保存后按 F9 开始。每次完整输入后的等待值位于区间内且可能变化；关闭后恢复固定延迟，手动 Enter 不受影响。

新增功能在以上实机项目执行前仍视为待联调，不能把编译与本地测试通过当成游戏内统计准确或退出问题已解决的证明。
